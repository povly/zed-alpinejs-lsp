# Правила парсинга (extractor.ts, xdata.ts)

> Area-специфичные конвенции для модулей парсинга Alpine-атрибутов и объектных литералов. Загружаются после rules/base.md.

## Правила

- Каждый новый edge-case, обнаруженный в реальном коде, обязан сопровождаться регрессионным тестом в `test/test.js` — без исключений
- Функции-парсеры (`extractAlpineAttrs`, `parseXData`, `matchBraces`, `extractAlpineData`, `extractAlpineStore`) должны быть pure: без побочных эффектов, без мутации внешнего состояния, без I/O
- `matchBraces` обязан корректно обрабатывать строки (одиночные `'`, двойные `"`, backtick `` ` ``), escape-последовательности `\\` и комментарии `//` до конца строки
- `valueOffset` — абсолютная позиция от начала документа, включает смещение открывающей кавычки + 1 (указывает на первый символ значения)
- Имена-члены объектных литералов фильтруются через `isValidMemberName`: JS-ключевые слова (`JS_KEYWORDS`), чистые числа (`/^\d+$/`), пустые строки отбрасываются
- Global regex (`/.../g`) перед использованием сбрасывать `lastIndex = 0` — иначе повторные вызовы пропускают совпадения
- Regex-паттерны хранить как именованные константы модуля (`ATTR_REGEX`, `methodRegex`, `propRegex`, `shortRegex`), не инлайнить
- Приоритет парсинга: методы → property keys → shorthand properties — порядок важен для дедупликации (`seen` Set)
- Дедупликация членов по имени: первое вхождение выигрывает, последующие пропускаются
- Нормализация имён атрибутов (`normalizeAttrName`): `x-on:click` → `@click`, `x-bind:class` → `:class` — каноническая форма для сравнений
